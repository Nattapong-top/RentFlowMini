# การออกแบบ UI: จัดการห้องพัก

เอกสารนี้กำหนดแนวทางปรับหน้าจอแท็บ “ข้อมูลห้องพัก” ให้ใช้งานง่ายและรองรับพื้นที่หน้าต่างที่เปลี่ยนแปลงได้

**สถานะ:** Implemented
**วันที่:** 2026-10-17
**ไฟล์หลัก:** `RentFlowMini/RentFlowApp/UI/RoomForm.cs`

## 1. ข้อกำหนดที่ยืนยันแล้ว

- รายการห้องเรียงตาม `RoomNumber` เช่น `101, 102, 201`
- ตารางต้องมีคอลัมน์ลำดับห้อง
- ตารางแสดงสถานะห้องว่า `ว่าง` หรือ `ไม่ว่าง`
- ตารางแสดงชื่อผู้เช่าของห้องที่มีผู้เช่า
- ไม่แสดง `RoomId` ในตาราง
- ยังเก็บ `RoomId` ในข้อมูลภายในได้ เพื่อใช้กับ flow อื่น
- ช่อง “ยกเว้นค่า Cable TV” ต้องไม่ชิดขอบหน้าต่างหรือชิดกับ control อื่นจนอ่านยาก
- แอปควรเปิดแบบหน้าต่างขยายเต็มพื้นที่หน้าจอ แต่ยังมี title bar และปุ่มควบคุมหน้าต่าง

## 2. Layout ที่เสนอ

```text
┌─────────────────────────────────────────────────────────────┐
│ ข้อมูลห้องพัก                                                │
│                                                             │
│ หมายเลขห้อง       [                         ]               │
│ ค่าเช่ารายเดือน   [                         ] บาท          │
│                    [ ] ยกเว้นค่า Cable TV                  │
│                                               [ เพิ่มห้อง ] │
├─────────────────────────────────────────────────────────────┤
│ รายการห้องพัก                                               │
│                                                             │
│ ลำดับ │ หมายเลขห้อง │ สถานะ │ ผู้เช่า │ ค่าเช่ารายเดือน │ ยกเว้น Cable TV │
│   1   │     101     │ ว่าง  │ -       │      2,800.00   │ ไม่             │
└─────────────────────────────────────────────────────────────┘
```

ส่วนกรอกข้อมูลควรอยู่ใน `GroupBox` ชื่อ “ข้อมูลห้องพัก” และส่วนตารางควรอยู่ใน `GroupBox` ชื่อ “รายการห้องพัก” เพื่อแยกหน้าที่ของแต่ละส่วนให้ชัดเจน

## 3. ตารางรายการห้อง

คอลัมน์ที่แสดง:

| ลำดับ | Data source | รูปแบบ |
|---|---|---|
| ลำดับ | คำนวณหลังเรียงข้อมูล | จำนวนเต็มเริ่มที่ 1 |
| หมายเลขห้อง | `Room.RoomNumber.Value` | ชิดซ้ายหรือกึ่งกลาง |
| สถานะห้อง | มีผู้เช่าผูกกับ `RoomId` หรือไม่ | แสดง `ว่าง` หรือ `ไม่ว่าง` |
| ผู้เช่า | ชื่อและนามสกุลจาก `Tenant` | แสดง `-` เมื่อไม่มีผู้เช่า |
| ค่าเช่ารายเดือน | `Room.MonthlyRent.Amount` | ตัวเลขชิดขวา รูปแบบ `N2` |
| ยกเว้น Cable TV | `Room.IsCableTvExempt` | แสดง `ใช่` หรือ `ไม่` |

ไม่สร้าง column สำหรับ `RoomId` ใน DataGridView จึงไม่แสดงรหัส GUID ยาว ๆ ให้ผู้ใช้เห็น แต่สามารถเก็บ `RoomId` ไว้ใน row model ภายในได้หากจำเป็น

การเรียง:

1. ให้ repository คืนข้อมูลเรียงตาม `RoomNumber`
2. UI สร้าง row model ตามลำดับข้อมูลที่ได้รับ
3. ใส่ลำดับเป็น `index + 1`

ในขอบเขตนี้ใช้การเรียงเลขห้องตามรูปแบบข้อมูลปัจจุบัน เช่น `101, 102, 201` ไม่เพิ่ม natural sort สำหรับรูปแบบผสมตัวอักษรหรือเลขห้องที่มีหลักไม่เท่ากัน

การแสดงผลที่แนะนำ:

- ตั้งความกว้างคอลัมน์ลำดับให้แคบ
- ตั้งความกว้างหมายเลขห้องและสถานะให้พอดีกับเนื้อหา
- ให้คอลัมน์ค่าเช่าขยายตามพื้นที่ที่เหลือหรือกำหนดความกว้างขั้นต่ำ
- จัด header ให้อยู่กึ่งกลาง
- จัดตัวเลขค่าเช่าให้ชิดขวา
- เปิดสีแถวสลับเพื่อช่วยอ่านข้อมูลหลายรายการ
- ปรับความสูงแถวและขนาดตัวอักษรให้เหมาะกับ DPI ของ Windows

## 4. ส่วนกรอกข้อมูล

แนะนำใช้ `TableLayoutPanel` เพื่อให้ label, input และ checkbox อยู่แนวเดียวกันแทนการกำหนดตำแหน่งแบบ absolute ทั้งหมด

แนวทางการจัดวาง:

- label อยู่คอลัมน์เดียวกัน
- TextBox ค่าเช่ามีความกว้างเท่ากับ TextBox หมายเลขห้อง
- Checkbox อยู่ในแถวของตัวเองและมีระยะห่างด้านซ้ายที่เหมาะสม
- ปุ่ม “เพิ่มห้อง” อยู่ด้านขวาล่างของกลุ่มข้อมูล
- มี padding รอบกลุ่มข้อมูลอย่างน้อย 16 pixels
- เมื่อเกิด error ให้แสดงข้อความใต้ส่วนกรอกข้อมูล ไม่ดันตารางจน layout เสีย

## 5. ขนาดและการเปิดหน้าต่าง

ใช้โหมด Maximized:

```csharp
WindowState = FormWindowState.Maximized;
```

ยังคงใช้ title bar ปกติ และไม่ใช้ `FormBorderStyle.None` เพื่อให้ผู้ใช้ย่อ ขยาย หรือปิดโปรแกรมได้ตามปกติ

การจัดพื้นที่:

- `TabControl` ใช้ `Dock = DockStyle.Fill`
- ส่วนกรอกข้อมูลอยู่ด้านบนและมีขนาดคงที่พอเหมาะ
- ตารางใช้ `Dock = DockStyle.Fill` หรือ anchor ทั้งสี่ด้าน
- หลีกเลี่ยงการกำหนดความกว้างตารางตายตัวจนเกิด horizontal clipping เมื่อเปิดเต็มจอ
