# การออกแบบและแผน Implement: ค่าเช่าห้องและ Cable TV

เอกสารนี้กำหนดการออกแบบและแผน Implement สำหรับการเพิ่มค่าเช่ารายห้อง และการรองรับการยกเว้นค่า Cable TV บางห้อง โดยจำกัดขอบเขตเริ่มต้นที่การจัดการข้อมูลห้องพักก่อน ยังไม่ลงมือแก้ source code หรือฐานข้อมูลตามเอกสารนี้

**สถานะ:** Phase Domain + In-Memory + UI เสร็จแล้ว; SQL Server รอทำ
**วันที่:** 2026-10-17
**ขอบเขต:** Room management และโครงสร้างที่ต้องเตรียมสำหรับ Billing
**เอกสารอ้างอิง:** `RentFlowApp/Room.cs`, `RentFlowApp/Domain/ValueObjects/Money.cs`, `RentFlowApp/Database/001_CreateRooms.sql`, `RentFlowApp/Database/002_CreateBills.sql`

## 1. ข้อกำหนดที่ยืนยันแล้ว

1. ห้องพักแต่ละห้องมีค่าเช่ารายเดือนของตัวเอง
2. ใช้ `Money` Value Object ที่มีอยู่แล้วสำหรับค่าเช่า
3. การยกเว้นมีผลเฉพาะ Cable TV ไม่ยกเว้นค่าเช่า
4. ราคาค่า Cable TV เป็นราคาเดียวกันทุกห้อง
5. ราคาค่า Cable TV ต้องเก็บเป็นค่ากลางแยกจากข้อมูลห้อง
6. ตอนสร้างบิลจึงค่อยโหลดราคาค่า Cable TV กลางมาใช้
7. ห้องที่ยกเว้นต้องไม่ถูกคิดค่า Cable TV แม้ว่าราคากลางจะมีค่าอยู่
8. บิลที่สร้างแล้วต้องเก็บยอดที่คิดจริงไว้ เพื่อไม่ให้การเปลี่ยนราคากลางในอนาคตเปลี่ยนยอดบิลเก่า
9. ผู้ใช้สามารถแก้ไขค่าเช่าของห้องที่มีอยู่แล้วได้
10. การแก้ไขนี้เปลี่ยนเฉพาะค่าเช่า ไม่เปลี่ยนหมายเลขห้องหรือสถานะยกเว้น Cable TV
11. อนุญาตให้ค่าเช่าใหม่เป็น `0`
12. ผู้ใช้ต้องเลือกแถวห้องก่อน แล้วกดปุ่มแก้ไขค่าเช่า

## 3. แบบจำลองข้อมูล

### 3.1 `Room` Domain Model

เพิ่ม property ดังนี้:

```csharp
public Money MonthlyRent { get; }
public bool IsCableTvExempt { get; }
```

แนวคิดสำคัญ:

- `MonthlyRent` เป็น `Money` ไม่ใช่ `decimal` ใน Domain
- `Money.Create(...)` เป็นจุดตรวจสอบค่าเงินไม่ให้ติดลบ
- `IsCableTvExempt` เป็น Boolean ที่สื่อความหมายโดยตรง
- ไม่เพิ่ม `CableTvAmount` ใน `Room` เพราะราคานี้เป็นราคาเดียวกันทุกห้อง

ตัวอย่างข้อมูลเชิงความหมาย:

| ห้อง | ค่าเช่า | ยกเว้น Cable TV | ค่า Cable TV ที่คิดในอนาคต |
|---|---:|:---:|---:|
| A101 | 5,000 | ไม่ | ราคากลาง |
| A102 | 5,000 | ใช่ | 0 |

### 3.2 SQL Server: `dbo.Rooms`

เพิ่ม column:

```sql
MonthlyRent DECIMAL(18, 2) NOT NULL DEFAULT 0,
IsCableTvExempt BIT NOT NULL DEFAULT 0
```

เหตุผลของ default:

- รองรับข้อมูลห้องเดิมที่มีอยู่ก่อน migration
- ห้องเดิมเริ่มต้นด้วยค่าเช่า `0` จนกว่าจะมีการกรอกค่าเช่า
- ห้องเดิมไม่ถือว่ายกเว้น Cable TV โดยอัตโนมัติ

> การใช้ default เป็นข้อเสนอสำหรับ migration เท่านั้น ต้องตรวจสอบกับข้อมูลจริงก่อนรันบนฐานข้อมูลจริง

### 3.3 ราคากลาง Cable TV

ราคากลางไม่อยู่ใน `Rooms` โดยควรมี model/repository แยกในเฟส Billing เช่น:

```text
BillingSettings
└── CableTvMonthlyRate: Money
```

การเก็บถาวรควรอยู่ในตารางตั้งค่ากลาง เช่น `dbo.BillingSettings` หรือรูปแบบที่สอดคล้องกับโครงสร้าง persistence ของโปรเจกต์ โดยต้องมีค่า Cable TV เพียงชุดเดียวสำหรับทุกห้อง

ในเฟส Billing ระบบจะทำงานตามลำดับ:

```text
โหลด Room
    ↓
โหลดราคากลาง Cable TV
    ↓
ถ้า Room.IsCableTvExempt = true → Cable TV = Money.Create(0)
ถ้าไม่ใช่ → Cable TV = CableTvMonthlyRate
    ↓
คำนวณและสร้าง Bill
```

## 4. ผลกระทบต่อโครงสร้างปัจจุบัน

| ส่วน | ไฟล์/องค์ประกอบ | การเปลี่ยนแปลง |
|---|---|---|
| Domain | `Room.cs` | รับและเปิดเผย `MonthlyRent`, `IsCableTvExempt` |
| Value Object | `Money.cs` | ใช้ของเดิม ไม่สร้าง money type ใหม่ |
| Application | `CreateRoomService` | รับค่าเช่าและสถานะยกเว้น พร้อมส่งเข้า `Room` |

| Contract | `IRoomRepository` | เพิ่ม `GetById` และ `Update` สำหรับแก้ค่าเช่า |

| Billing ภายหลัง | `Bill`, `BillingCalculator`, `002_CreateBills.sql` | เพิ่มยอด Cable TV และโหลดราคากลางในเฟสถัดไป |

## 5. แผนการ Implement

4. ใช้ `Money.Create(...)` ก่อนส่งค่าเข้า Domain
5. เพิ่มหรือปรับ unit tests สำหรับค่าเช่าปกติ ค่าเช่าเป็นศูนย์ และค่าติดลบ

### Phase 2: ปรับ Application และ Repository

เป้าหมาย: ให้ข้อมูลใหม่เดินทางครบจาก service ถึง storage

งาน:

1. ปรับ `CreateRoomService` ให้รับค่าเช่าและสถานะยกเว้น
2. ปรับ In-Memory repository และ tests

4. ปรับ `SqlServerRoomRepository` ให้บันทึกและอ่านข้อมูลใหม่
5. เพิ่ม integration tests ตรวจสอบค่าที่บันทึกและอ่านกลับได้ตรงกัน

### Phase 3: ปรับ Room UI

เป้าหมาย: ให้ผู้ใช้ตั้งค่าห้องได้จากหน้าจอ

งาน:

1. เพิ่มช่อง “ค่าเช่ารายเดือน”

4. แสดงข้อความ error ภาษาไทยเมื่อค่าเช่าไม่ถูกต้อง
5. แสดงค่าเช่าและสถานะยกเว้นในรายการห้อง
6. ทดสอบ flow เพิ่มห้องและตรวจสอบผลลัพธ์บนหน้าจอ

เป้าหมาย: ให้ผู้ใช้เลือกห้องและแก้ไขเฉพาะค่าเช่าได้

5. โหลดค่าเช่าปัจจุบันของแถวที่เลือกมาแสดงก่อนแก้ไข
6. บันทึกค่าใหม่โดยอนุญาตค่า `0` และปฏิเสธค่าติดลบ

7. เก็บยอด Cable TV ที่คิดจริงลงบิลเป็น snapshot

## 6. กฎและกรณีทดสอบที่ต้องมี

### Room Domain

- สร้างห้องด้วยค่าเช่ามากกว่าศูนย์ได้
- สร้างห้องด้วยค่าเช่าเป็นศูนย์ได้ หากธุรกิจอนุญาตห้องฟรี
- ปฏิเสธค่าเช่าติดลบผ่าน `Money`
- ห้องปกติมี `IsCableTvExempt = false`
- ห้องยกเว้นมี `IsCableTvExempt = true`
- การยกเว้นไม่เปลี่ยนค่า `MonthlyRent`
- เปลี่ยนค่าเช่าเป็นจำนวนบวกได้
- เปลี่ยนค่าเช่าเป็น `0` ได้
- เปลี่ยนค่าเช่าติดลบไม่ได้
- การเปลี่ยนค่าเช่าไม่เปลี่ยน Room ID, หมายเลขห้อง หรือสถานะยกเว้น Cable TV

### Persistence

- บันทึกและอ่าน `MonthlyRent` ได้ตรงจำนวนเงิน
- บันทึกและอ่าน `IsCableTvExempt` ได้ทั้ง true และ false
- ห้องเดิมหลัง migration ได้ค่า default ตามที่กำหนด

### Billing ในเฟสถัดไป

- ห้องปกติได้รับราคากลาง Cable TV
- ห้องยกเว้นได้รับ Cable TV เป็นศูนย์
- การยกเว้นไม่ทำให้ค่าเช่าเป็นศูนย์
- การเปลี่ยนราคากลางไม่เปลี่ยนยอดบิลเก่า
- ไม่พบราคากลางต้องหยุดสร้างบิลและแจ้งข้อผิดพลาดที่เหมาะสม

## 7. ความเสี่ยงและจุดที่ต้องตัดสินใจ

1. **ข้อมูลห้องเดิม:** ต้องยืนยันว่าจะตั้งค่าเริ่มต้นของค่าเช่าเป็น `0` แล้วให้ผู้ดูแลกรอกภายหลัง หรือมีข้อมูลค่าเช่าเดิมสำหรับ backfill
2. **ห้องค่าเช่าเป็นศูนย์:** เอกสารนี้เสนอให้ `Money` อนุญาตศูนย์ตาม implementation ปัจจุบัน แต่ต้องยืนยันกับกฎธุรกิจ
3. **การเก็บราคากลาง:** ต้องเลือกว่าจะเก็บในตาราง `BillingSettings` หรือ configuration ของระบบ ก่อนเริ่ม Phase 4
4. **การเปลี่ยนราคากลาง:** ราคาที่เปลี่ยนมีผลกับบิลรอบใหม่เท่านั้น ไม่ควร recalculate บิลที่สร้างแล้วโดยอัตโนมัติ
5. **Migration ฐานข้อมูล:** ต้องทดสอบกับฐานข้อมูลเดิมในสภาพแวดล้อมปลอดภัยก่อนใช้จริง และยังห้ามรันกับฐานข้อมูลจริงจนกว่าจะได้รับอนุมัติ
