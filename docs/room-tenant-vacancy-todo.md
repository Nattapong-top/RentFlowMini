## กติกาการออกบิลที่ยืนยันแล้ว

ทำแล้วพร้อมกับการแก้ไขสถานะยกเว้น Cable TV ของห้อง: `CreateMonthlyBillService` ปฏิเสธบิลที่ไม่มีผู้เช่า แท็บสร้างบิลซ่อนห้องว่าง และกล่องยืนยันย้ายออกเตือนเมื่อห้องยังไม่มีบิลของเดือนที่ย้ายออก

- ห้ามออกบิลให้ห้องที่ไม่มีผู้เช่า เพราะบิลนั้นไม่มีผู้รับผิดชอบยอดเงิน
- เมื่อผู้เช่าย้ายออก ต้องออกบิลเดือนสุดท้ายก่อนบันทึกการย้ายออก โดยออกแยกเฉพาะห้องนั้น
- บิลเดือนสุดท้ายคิดค่าเช่าเต็มเดือน แม้ย้ายออกกลางเดือน
- ค่าน้ำและค่าไฟคิดตามเลขมิเตอร์ถึงวันที่อยู่จริง
- ผู้เช่าใหม่ของห้องที่ออกบิลเดือนสุดท้ายแล้วเริ่มเข้าอยู่และเริ่มคิดเงินในเดือนถัดไป เพราะหนึ่งห้องมีบิลได้หนึ่งใบต่อรอบบิล
- หากบันทึกการย้ายออกโดยห้องยังไม่มีบิลของเดือนที่ย้ายออก (ตามวันที่ย้ายออก ไม่ใช่วันที่กดปุ่ม) ระบบแสดงคำเตือนให้ตรวจสอบบิล แต่ผู้ใช้ยืนยันการย้ายออกต่อได้ เพราะอาจบันทึกการย้ายออกล่าช้าหลังผู้เช่าออกไปและชำระบิลครบแล้ว

## กติกาการแก้บิลที่ออกผิดที่ยืนยันแล้ว

ทำแล้ว: ปุ่มดึงข้อมูลห้องใหม่ ร่างบิลตอนแก้ไข และร่างบิลตอนออกบิล ยังออกบิลใหม่ในรอบเดิมไม่ได้ เพราะหนึ่งห้องมีบิลได้หนึ่งใบต่อรอบบิล

- แก้ข้อมูลต้นทางก่อน คือค่าเช่าหรือสถานะยกเว้น Cable TV ที่ห้อง หรือเลขมิเตอร์ของรอบบิลนั้น เพื่อให้รอบถัดไปไม่ผิดซ้ำ
- ในโหมดแก้ไขบิลมีปุ่ม "ดึงข้อมูลห้องใหม่" ใช้ได้เฉพาะบิลที่ยังไม่ชำระ บิลที่ชำระแล้วต้องยกเลิกการรับชำระก่อน
- ปุ่มนี้ดึงค่าเช่า สถานะยกเว้น Cable TV และเลขมิเตอร์ของรอบนั้นลงช่องในโหมดแก้ไข แต่ยังไม่บันทึก ถ้าบิลไม่ได้เก็บอัตราค่าน้ำและค่าไฟไว้ หรือรอบนั้นไม่มีเลขมิเตอร์ จะดึงได้เฉพาะค่าเช่าและสถานะยกเว้น Cable TV พร้อมแจ้งเหตุผล
- ตอนกดบันทึก ถ้ายอดรวมเปลี่ยน ระบบแสดงยอดเดิมเทียบยอดใหม่ให้ยืนยัน ถ้าตอบ "ไม่" บิลที่บันทึกไว้ไม่เปลี่ยนและยังอยู่ในโหมดแก้ไข
- บิลไม่เปลี่ยนเองโดยอัตโนมัติ ถ้าผู้ใช้ไม่สั่ง บิลยังคงยอดเดิม
- การอัปเดตใช้อัตราค่าน้ำและค่าไฟเดิมในบิล คำนวณยอดรวมใหม่ และคงเลขใบแจ้งหนี้กับวันที่ออกบิลเดิม
- กล่องสรุปแสดงร่างที่ยังไม่บันทึก โดยหัวกล่องเป็น "สรุปรายละเอียดบิล (ร่าง ยังไม่บันทึก)"
  - ตอนแก้ไขบิล ร่างคำนวณใหม่เมื่อกดดึงข้อมูลห้องใหม่และเมื่อเปลี่ยน checkbox ค่าจอดรถหรือยกเว้น Cable TV
  - ตอนออกบิล ร่างคำนวณใหม่เมื่อเลือกห้อง เปลี่ยนรอบบิล หรือเปลี่ยน checkbox ร่างยังไม่มีเลขใบแจ้งหนี้และวันที่ออกบิล และไม่จองเลข ปุ่มออกบิลคำนวณยอดใหม่เสมอ
  - หลังออกบิล ระบบเลื่อนไปห้องถัดไปและแสดงร่างของห้องนั้นทันที ถ้าไม่เหลือห้องให้ออกบิล กล่องสรุปยังแสดงบิลที่เพิ่งออก
  - ถ้าคำนวณร่างไม่ได้ เช่น ยังไม่ได้บันทึกมิเตอร์ของรอบนั้น กล่องสรุปเป็น "-" และแสดงเหตุผลในข้อความใต้ปุ่ม ยกเว้นหลังออกบิลที่ข้อความใต้ปุ่มยังแสดงผลการออกบิล
- ยังไม่เก็บประวัติการแก้ไขยอด หลังบันทึกที่ยอดเปลี่ยน ระบบเตือนให้พิมพ์บิลใหม่ถ้าเคยพิมพ์ให้ผู้เช่าแล้ว
- ยังไม่ทำการยกเลิกบิล การลบบิล และการปรับค่าเช่าเฉพาะเดือนเดียว
- แก้เลขมิเตอร์ของรอบที่บิลชำระแล้วไม่ได้ ต้องยกเลิกการรับชำระก่อน ถ้าบิลรอบนั้นยังไม่ชำระ ระบบบันทึกเลขมิเตอร์แล้วเตือนให้เปิดบิลและกดดึงข้อมูลห้องใหม่ (ทำแล้ว)

**สถานะ:** ยังไม่ได้ทำ บันทึกไว้หลังปล่อยเวอร์ชันทดลองใช้

ตอนนี้ระบบเก็บยอดเงินประกันของผู้เช่าไว้อย่างเดียว ยังไม่มีการหักหรือคืน และกล่องยืนยันย้ายออกเตือนเฉพาะยอดค้างชำระกับบิลของเดือนที่ย้ายออก ไม่ได้พูดถึงเงินประกัน ผู้ใช้จึงอาจลืมคืนเงินประกัน

สิ่งที่ต้องการ:

- ตอนย้ายออก ระบบต้องแจ้งว่าผู้เช่ามีเงินประกันเท่าไร และถามว่าคืนเงินประกันแล้วหรือยัง

เรื่องที่ต้องตัดสินใจก่อนทำ:

1. ต้องบันทึกยอดที่คืน วันที่คืน และช่องทางการคืนหรือไม่
2. หักเงินประกันได้หรือไม่ เช่น ค่าเสียหายหรือยอดค้างชำระ และต้องบันทึกเหตุผลการหักหรือไม่
3. ถ้ายังไม่คืนเงินประกันตอนย้ายออก ให้ย้ายออกได้พร้อมเตือน หรือห้ามย้ายออก
4. เงินประกันที่ยังไม่คืนต้องแสดงในรายงานหรือในตารางผู้เช่าที่ย้ายออกแล้วหรือไม่

## แนวทางที่เสนอ

ไม่ควรลบข้อมูล `Tenant` เมื่อผู้เช่าย้ายออก เพราะอาจทำให้ประวัติและความสัมพันธ์กับบิลเดิมหายไป

แนวทางที่ควรพิจารณา:

```text
TenantOccupancyHistory
├── TenantId
├── RoomId
├── MoveInDate
└── MoveOutDate (nullable)
```

ห้องจะมีสถานะดังนี้:

- `ไม่ว่าง` เมื่อมีรายการ occupancy ที่ยังไม่มี `MoveOutDate`
- `ว่าง` เมื่อไม่มีรายการ occupancy ที่ยังใช้งานอยู่
- ชื่อผู้เช่าปัจจุบันมาจากรายการ occupancy ที่ยังใช้งานอยู่

## งานที่คาดว่าจะต้องทำ

### Domain และ Application

- กำหนด model สำหรับประวัติการเข้าพัก หรือเพิ่มสถานะผู้เช่าตาม business rule ที่ยืนยันแล้ว
- เพิ่ม service สำหรับย้ายออก
- ป้องกันการย้ายออกซ้ำ
- ป้องกันการผูกผู้เช่าซ้ำในห้องเดียวกัน
- อนุญาตให้ห้องที่ว่างแล้วรับผู้เช่ารายใหม่ได้

### Persistence

- ออกแบบ schema และ migration สำหรับสถานะหรือประวัติการเข้าพัก
- ปรับ repository ให้ค้นหาผู้เช่าปัจจุบันของห้องได้
- เพิ่ม integration tests สำหรับการย้ายเข้าและย้ายออก

### UI

- เพิ่มปุ่มหรือคำสั่ง “แจ้งย้ายออก” ในจุดที่ยืนยันแล้ว
- แสดงวันที่ย้ายออกและประวัติเมื่อจำเป็น
- หลังย้ายออกต้อง refresh ตารางห้องให้แสดง `ว่าง` และผู้เช่าเป็น `-`
- ต้องแสดงข้อความยืนยันก่อนดำเนินการ หากการย้ายออกมีผลกับข้อมูลประวัติ
- เพิ่มจุดแก้ไขราคากลาง Cable TV ตามตำแหน่ง UI ที่ยืนยันแล้ว
- แสดงค่า Cable TV ในหน้าสร้างบิลและผลสรุปบิล
